## 5. 生产部署目标结构

推荐保持同源访问：

```text
浏览器
  ├── /                 → OpenResty 静态前端
  └── /api/*            → OpenResty → cet-word-api:3000 → Node API
                                                    ↓
                                                MySQL 私有网络
```

部署约束：

- MySQL 不发布到公网，不映射宿主机 3306。
- Node API 不映射宿主机端口；它只加入 MySQL 私有网络和 OpenResty 已在使用的 Docker 网络。
- `cet-word-api` 是 API 在共享 Docker 网络上的私有别名。OpenResty 也是容器，不能把它的 `127.0.0.1` 误当宿主机 API。
- OpenResty 的 `/api/` 必须反代到 Node API，不能回退到 `index.html`。
- API 失败必须保留 JSON 状态码，例如未登录为 401、接口不存在为 404。
- 静态前端完整上传 `dist/` 内容，网站根目录直接包含 `index.html` 和 `assets/`。
- 发布前备份当前静态目录；不要逐个覆盖线上文件造成新旧 hash 资源混用。

### 阶段 E：启动 API 与反代

API 启动后，OpenResty 应通过共享 Docker 网络访问私有别名 `cet-word-api:3000`。
不要在 OpenResty 配置中使用 `127.0.0.1:3000`，它只指向 OpenResty 容器自己。反代
reload 后从同源入口验证：

```bash
curl -sS -i http://<实际站点>/api/health
curl -sS -i http://<实际站点>/api/ready
curl -sS -i http://<实际站点>/api/auth/me
```

期望：

- `/api/health`：200 JSON。
- `/api/ready`：200 JSON，`database` 为 `up`。
- `/api/auth/me`：未携带 Cookie 时为 401 JSON。

OpenResty 站点配置应在备份后加入等价逻辑：

```nginx
location ^~ /api/ {
    proxy_pass http://cet-word-api:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Cookie $http_cookie;
    proxy_pass_request_body on;
    proxy_intercept_errors off;
}

location = /api {
    return 404;
}
```

每次变更后先验证再 reload：

```bash
cp /opt/1panel/www/conf.d/cet-word-web.conf /opt/1panel/www/conf.d/cet-word-web.conf.bak-$(date +%Y%m%d-%H%M%S)
docker exec openresty nginx -t
docker exec openresty nginx -s reload
```

## 8. 回滚与禁止动作

### 回滚

- API 启动失败：先保留日志和 `.env` 权限，停止新 API 容器，不能删除 MySQL 数据卷。
- OpenResty 配置失败：恢复最近一次 `.bak-*`，执行 `docker exec openresty nginx -t && docker exec openresty nginx -s reload`。
- 静态页面异常：恢复上线前保存的完整静态目录或上一版发布目录。
- migration 失败：停止并检查 `schema_migrations` 与实际表结构，不要盲目重复执行或手工删除表。

### 禁止动作

- 不在聊天中索取或粘贴 SSH 密码、数据库密码、初始账号密码、Cookie 或 `SESSION_SECRET`。
- 不使用带 `--password` 的命令行参数创建账号。
- 不把 MySQL 3306、Node API 3000 直接暴露到公网。
- 不执行 `rm -rf`、`git reset --hard`、`git clean -fd` 或删除旧回退资产。
- 不把 HTTP + `COOKIE_SECURE=false` 当作正式生产登录完成。
- 不把只通过 fake repository 的测试写成真实 MySQL 已验证。
- 不把“认证已接入”写成“词库已云同步”。
