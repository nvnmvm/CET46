## 1. 任务目标

本轮先完成前端内部精简，确认现有 UI、功能、数据和交互均未变化后，立即生成生产构建并进入 1Panel 静态部署。

这里的“精简”不是删功能、重做界面或改技术栈，而是：

1. 拆开过大的源码文件，让每个文件只负责一类事情。
2. 合并重复的弹窗、进度条和学习界面结构。
3. 将 localStorage、复习、备份、用户设置等职责分层。
4. 清理确认无用的导入、常量和死代码。
5. 保持构建产物轻量，并让以后接 1Panel + API + MySQL 时更容易替换数据层。

本轮不做数据库、服务器账号、跨设备同步和复习算法升级。部署完成后，网站仍是浏览器 localStorage 版本。

## 2. 不可改变的兼容边界

以下内容是本次重构的硬性边界。任何一步触碰这些行为，都应停止并回到该阶段开始前的版本。

### 2.1 UI 与交互

- 不修改现有文字、颜色、字号、圆角、布局比例和图标。
- 不修改手机端、平板端、电脑端的断点和显示结果。
- 不修改日间、夜间、跟随系统三种主题的效果。
- 不修改按钮顺序、按钮含义、键盘操作、返回行为、弹窗关闭方式和焦点行为。
- 不增加新的 loading 页面、动画、路由库、组件库或状态管理库。
- 保留现有 hash 路由，包括 `#/`、`#/words`、`#/profile`、`#/import`、`#/statistics`、`#/review/new`、`#/review/review`、`#/spell` 和 `#/login`。

### 2.2 本地数据

- 保留现有 localStorage 键名，不能为了目录整洁而改名。
- 保留 `cet-word-mvp-local-v1` 主数据格式和版本号。
- 保留用户档案、倒数日、主题、每日组数、每组词数、学习草稿和自动备份的现有键名。
- 保留旧数据迁移、损坏数据保护、写入锁和恢复前自动备份逻辑。
- 重构前导出的 JSON 必须能在重构后恢复；重构后导出的 JSON 也必须保持当前格式。

### 2.3 学习规则

- 新学、复习、首页拼写、词库分组拼写继续使用两套独立计算逻辑。
- 每日新词组数、每组词数、每日新词上限的计算结果不能变化。
- 到期复习数量、错词回炉、拼写订正、评分、阶段和下次复习日期不能变化。
- 主动斩词、撤销、恢复和系统已掌握必须继续分开计算。
- 学习草稿的队列、当前位置、输入、首次选择和恢复行为不能变化。
- 独立拼写不能推进复习层级，也不能伪造认词结果。

### 2.4 导入导出

- TSV 继续严格使用 8 列：`word / phonetic / meaning / phrase / sentence / sentence_cn / source / type`。
- TSV 列顺序、表头、Tab 分隔、同词合并和 `marked` 优先规则不能变化。
- 词库 TSV 导出后必须可以重新导入。
- JSON 备份、恢复预检、失败不部分写入等行为不能变化。

## 10. 阶段 4：拆分 localStore 内部职责

这是风险最高的阶段，必须在页面拆分稳定后进行。

### 10.1 对外接口保持不变

`app/src/data/repository.ts` 继续作为页面唯一入口。`localStore` 的公开方法名称、参数、同步返回方式和异常行为都保持不变。

第一轮不要把同步 localStorage 改成 Promise，也不要提前设计 HTTP API。

### 10.2 拆分顺序

#### 第一步：键名和纯校验

移动到 `data/storage/keys.ts` 和纯校验模块：

- 主存储、草稿、备份、主题、档案、倒数日和学习计划键名。
- `isRecord`、日期校验、草稿字段校验。

键名字符串必须逐字一致。

#### 第二步：底层数据库读写

移动到 `data/storage/database.ts`：

- `emptyDatabase`。
- `read`、`write`。
- 损坏数据保护。
- Web Locks 或旧快照检查。
- 数据迁移和规范化入口。

要求：所有上层模块仍通过同一底层读写，不允许各自直接读写主键造成竞争。

#### 第三步：用户档案与设置

移动到：

- `profileStore.ts`：登录、本地用户 ID、用户名、头像。
- `settingsStore.ts`：主题、倒数日、每日目标、每日组数和每组词数。

特别复验邮箱标点不会合并用户，设置继续按用户隔离，主题继续是设备级偏好。

#### 第四步：词库操作

移动到 `wordStore.ts`：

- 获取词库。
- 导入与同词合并。
- 编辑音标和释义。
- 批量删除、单词删除。
- 斩词、撤销和恢复。

导入和删除必须保留进度关联规则，不能产生孤立 progress。

#### 第五步：草稿

移动到 `draftStore.ts`：

- 获取、保存和清除草稿。
- 队列清理与失效词处理。
- `new`、`review`、`spell` 入口隔离。

草稿 JSON 结构和版本保持兼容。

#### 第六步：备份恢复

移动到 `backupStore.ts`：

- 导出备份。
- 解析与完整校验。
- 恢复前自动备份。
- 损坏存储下载和解锁。

恢复必须继续满足“全部成功或全部失败”，不能在校验完成前写入一部分数据。

#### 第七步：学习完成与调度

将纯计算拆到 `data/review/`：

- stage、认词分数、拼写分数计算。
- 下次复习日期计算。
- 新学完成。
- 复习完成。
- 独立拼写完成。
- 学习事件记录。

`localStore` 仍负责事务式读取、调用纯计算、写回和去重。不要让 UI 直接调用 scheduler。

不要为了复用把两个弹窗的业务提示强行合并。完成天数只属于每日组数弹窗，每组词数保持单列滚轮。

### 11.2 确认弹窗

斩词和批量删除可以复用通用确认框外壳，但保留不同标题、说明、危险级别和按钮文字。

### 11.3 学习进度

保留一个 `ReviewProgress`，供新学、复习和拼写复用。内容通过明确 props 传入，不读取隐藏的全局状态。

### 11.4 不要过度抽象

以下情况不要合并：

- 只是视觉相似，但提交逻辑不同。
- 需要传入十几个布尔值才能复用。
- 合并后必须在公共组件中判断当前页面。
- 抽取后代码行数反而增加且更难理解。

### 11.5 完成标准

总代码量预计可以降低约 5%—15%，但以可读性和行为一致为第一优先级。

## 12. 阶段 6：拆分 CSS

CSS 最容易因级联顺序产生“看起来差不多”的回归，因此最后处理。

### 12.1 拆分策略

按照原文件从上到下移动，并在 `styles/index.css` 中按原顺序导入：

```css
@import "./base.css";
@import "./theme.css";
@import "./layout.css";
@import "./components.css";
@import "./pages.css";
```

实际导入顺序必须根据当前 `index.css` 的选择器顺序确定，上面只表示职责划分。

### 12.2 规则

- 不重命名 className。
- 不调整选择器权重。
- 不把已有明确 transition 改成 `transition: all`。
- 不顺手改 margin、padding、颜色、断点或动画。
- 不把 media query 合并到会改变覆盖顺序的位置。
- `prefers-reduced-motion`、hover/pointer 条件和夜间覆盖必须保留。
- Tailwind 扫描路径和生成结果保持不变。

### 12.3 视觉回归矩阵

每个主要页面至少比较：

| 视口 | 日间 | 夜间 |
| --- | --- | --- |
| 390 × 844 | 必测 | 必测 |
| 768 × 1024 | 首页、词库、弹窗 | 首页、词库、弹窗 |
| 1440 × 900 | 必测 | 必测 |

重点检查：固定底栏、顶部栏、滚轮居中、弹窗高度、中文释义 hover、词库悬浮操作栏和安全区域。

## 13. 阶段 7：清理死代码与测试整理

### 13.1 可清理内容

## 17. 风险清单

| 风险 | 最可能发生的阶段 | 防护方式 |
| --- | --- | --- |
| 循环依赖导致组件或常量初始化异常 | 页面拆分 | 单向依赖：App → 页面 → 公共组件/数据，不反向导入 App |
| localStorage 键名或格式变化 | 数据层拆分 | 键名集中但字符串不变，使用重构前真实备份回归 |
| 复习日期因 Date 调用时机变化 | 调度拆分 | 固定 now 的单元测试，保持本地日历/UTC 用法 |
| CSS 覆盖顺序变化 | 样式拆分 | 严格按原顺序移动，逐页截图比较 |
| 草稿入口互相覆盖 | 学习页和 draftStore | 覆盖 new/review/spell 三类草稿测试 |
| 重复提交增加分数 | 学习页和完成逻辑 | 保留 stale completion 和连点提交测试 |
| 构建包混入旧哈希资源 | 部署 | 使用完整新目录切换，不逐文件覆盖 |
| Service Worker 继续使用旧版本 | 部署 | 核对缓存版本、无缓存访问和更新流程 |
| 正式域名看不到本地词库 | 部署 | 上线前导出 JSON，上线后明确恢复 |
