## 本批目标

新增一个独立、可测试、不会自动启用的前端 API 客户端：

1. `app/src/data/apiClient.ts`：统一请求、Cookie、JSON 错误解析和后端 DTO → 前端类型映射。
2. API 客户端覆盖认证、词库、设置、事件、学习队列、草稿、三类完成提交。
3. 客户端不得把 `userId` 放进 URL、query 或 body；参数中的 `userId` 只用于本地响应映射，服务端身份仍由 Cookie 决定。
4. `spelling.correct` 作为兼容字段发送，但客户端不得把它当作安全边界；服务端会重算。
5. `VITE_API_BASE_URL` 可配置，默认同源空字符串；所有请求 `credentials: include`。
6. 新增 `app/tests/apiClient.test.mjs`，用 fake fetch 验证请求路径、Cookie credentials、body 不含 userId、响应映射和错误解析。

## API 客户端要求

导出：

- `ApiError extends Error`：包含 `status`、`code`、`details`，错误信息不包含秘密或完整响应体。
- `createApiClient(options?)`：允许注入 `fetchImpl` 和 `baseUrl`，方便测试。
- `apiClient`：使用默认 `fetch`、`VITE_API_BASE_URL` 的单例。

请求基础规则：

- `fetch(url, { credentials: "include", headers: { "content-type": "application/json" } })`。
- `GET` 不强行发送 body。
- 非 2xx 读取受控 JSON error；非 JSON/网络错误转为通用 `ApiError`。
- 401 的 `session()` 返回 `null`；其他 API 401 必须抛出 `ApiError`。
- 不记录请求 body、Cookie、密码或 token。

建议方法契约：

```ts
login(email: string, password: string): Promise<LocalUser>
session(): Promise<LocalUser | null>
logout(): Promise<void>
listWords(userId: string, options?: { limit?: number; offset?: number }): Promise<{ total: number; words: WordWithProgress[] }>
importWords(input: WordInput[]): Promise<{ added: number; existing: number; total: number }>
updateWord(userId: string, wordId: string, phonetic: string, meaning: string): Promise<WordWithProgress>
deleteWord(userId: string, wordId: string): Promise<void>
progressAction(userId: string, wordId: string, action: "kill" | "restore" | "undo-kill"): Promise<Progress>
getSettings(): Promise<{ dailyTarget: number; dailyGroups: number; dailyGroupWords: number; dailyPlanConfigured: boolean; timezone: string; countdown: CountdownSettings | null; updatedAt: string }>
updateSettings(patch: { dailyTarget?: number; dailyGroups?: number; dailyGroupWords?: number; timezone?: string; countdown?: CountdownSettings | null }): Promise<...>
listEvents(options?: { limit?: number; offset?: number }): Promise<{ total: number; events: LearningEvent[] }>
getDue(limit?: number): Promise<{ reviewWords: WordWithProgress[]; newWords: WordWithProgress[]; ... }>
getSpelling(options?: { scope?: "daily" | "library"; filter?: string; limit?: number }): Promise<WordWithProgress[]>
getDraft(key: string): Promise<ReviewDraft | null>
saveDraft(draft: Omit<ReviewDraft, "userId" | "updatedAt">): Promise<ReviewDraft>
clearDraft(key: string): Promise<void>
completeNewStudy(userId: string, entries: WordWithProgress[]): Promise<{ completed: number; conflicts: number; skipped: number; earliestNextReviewAt: string | null }>
finishReview(userId: string, entries: WordWithProgress[], recognition: Record<string, RecognitionResponse>, spelling: Record<string, SpellingResponse>): Promise<ReviewCompletion & { conflicts: number; skipped: number }>
finishSpellingPractice(userId: string, entries: WordWithProgress[], spelling: Record<string, SpellingResponse>): Promise<{ completed: number; corrected: number; conflicts: number; skipped: number }>
```

客户端生成 `submissionKey`（受限字符集、至少 8 位），同一调用重试必须复用 key；不要使用时间戳拼接过长或把答案全文放入 key。若方法内部生成 key，测试必须验证格式和单次调用 body。

## 映射要求

- 词条响应没有 `userId`；映射时使用传入的 `userId`，不得从响应猜测。
- `progress.firstLearnedAt` 为 `null` 时映射为 `undefined` 或保持类型兼容；其它 nullable 字段保持 `null`。
- 登录用户的 `username`/`avatar` 为 null 时映射为 `undefined`，不要写入本地 storage。
- API draft 的 `key` 映射为前端 `ReviewDraft` 所需的字段；如果客户端类型比服务端 payload 更严格，先以安全的未知 payload 适配，不要丢弃字段。
- 服务端返回的 `updatedAt`、`nextReviewAt` 必须原样保留，完成提交只发送客户端观察到的版本。

## 测试

至少覆盖：

- `login`：POST `/api/auth/login`，body 有 email/password，credentials 为 include，返回用户映射。
- `session`：401 返回 null，非 401 错误抛 `ApiError`。
- `listWords`：GET query 只有 limit/offset，body 为空，响应不需要 userId 也能映射。
- `importWords` / `updateWord` / `deleteWord`：路径和 body 正确，body 没有 userId。
- `saveDraft` / `completeReview`：body 字段正确，提交输入中的客户端 stage/score 不应被客户端转发为最终结果。
- 非 JSON 500 和 JSON 401 错误都转为受控 `ApiError`。
- 运行现有 `corepack pnpm test`、`corepack pnpm run typecheck:server`、`corepack pnpm run build`；本批应不改动后端行为。
