# 服务器修复执行手册（静态站收尾）

> 本手册不含密码、密钥或 1Panel 安全入口。登录方式由操作员在 Control UI 终端里手工完成。

## 1. 交互方式（重要，先读）

1. 终端面板由操作员打开、终端会话由操作员创建；执行者不能自己开 shell。
2. 操作员在终端里执行 `ssh root@47.108.49.246` 并手工输入密码。执行者既不持有凭据，也不安装 SSH 公钥。
3. 执行者用 `terminal` 工具：`list` 找会话 → `read` 看输出 → `input` 发命令。
4. **一次只发一条命令**，发完先 `read` 确认提示符回来再发下一条。每次 `input` 可能需要操作员一次性批准，等待即可。
5. 不要用交互式编辑器（vim/nano）。改配置一律用「备份 + 单行写入/sed」。

## 2. 第 1 步：只读排查（不改任何东西）

依次执行，保存原始输出：

1. `hostname && uptime`
2. `docker ps --format '{{.Names}}|{{.Image}}|{{.Status}}|{{.Ports}}'`
3. `ss -lntp`
4. `ufw status verbose; iptables -S | head -30`
5. `ls -la /opt/1panel/www/conf.d/ /opt/1panel/www/sites/cet-word-web/`
6. `cat /opt/1panel/www/conf.d/cet-word-web.conf`

判定规则：

| 观察 | 结论 | 动作 |
| --- | --- | --- |
| `ss -lntp` 无 3306/33060 监听，`docker ps` 无 mysql/mariadb 容器 | 当前无数据库层 | 报告写「未发现数据库」，**不要安装任何数据库** |
| 3306 监听在 `127.0.0.1` 或容器内网 | 正常 | 记录即可 |
| 3306 监听在 `0.0.0.0`/`::`，或容器把端口发布到公网 | 数据库端口可能对外可及 | **停手报告**，附 `ss -lntp` 原文，由用户决定是否收口；不要擅自停服务、改密码或改安全组 |
| 站点配置里缓存由 `location ~` 正则统一下发 | 见第 2 步的写法 | 用精确匹配 location 覆盖，不改原有正则 |

注意：从外部对这个 IP 做端口扫描是**不可信**的（本机出网会被中间设备应答，连 `example.com` 上必然关闭的端口都报 open）。端口结论只能取自服务器上的 `ss -lntp`。

## 3. 第 2 步：修四处（先备份）

```bash
cp /opt/1panel/www/conf.d/cet-word-web.conf /opt/1panel/www/conf.d/cet-word-web.conf.bak-$(date +%Y%m%d-%H%M%S)
```

在 `server { ... }` 块内、`location /` **之前**加入这四组规则：

```nginx
    location ^~ /api/ {
        return 404;
    }

    location = /sw.js {
        add_header Cache-Control "no-cache" always;
    }

    location = /manifest.webmanifest {
        default_type application/manifest+json;
        add_header Cache-Control "no-cache" always;
    }

    location = /index.html {
        add_header Cache-Control "no-cache" always;
    }
```

理由，执行时不要自行改动：

- nginx 匹配优先级是 `=`（精确）> `^~`（前缀）> 正则 > 前缀，所以这些精确匹配会覆盖任何通用缓存规则，不必动原有正则。
- `/api/` 必须返回 404：当前没有后端，SPA 回退会把 `/api/*` 变成 `200 + index.html`（实测 `/api/health`、随机路径都返回 1196 字节首页）。接上后端后，这会让 401/404/500 全部变成 200，是最难排查的一类故障。后端上线时把这一块换成 `proxy_pass`，参考 `project/deploy/1panel/openresty.conf.example`。
- `location = /index.html` 同时覆盖对 `/` 的访问：`try_files $uri $uri/ /index.html` 会内部重定向到 `/index.html`。
- `manifest.webmanifest` 现场返回过 `application/octet-stream`，所以要显式设为 `application/manifest+json`。
- `/assets/` 的 7 天 `immutable` **不要改**，文件名带 hash，这个设置是对的。
- 现场观察到一个症状：同一响应会下发**两条** `Cache-Control`（`max-age=604800` 与 `public, immutable` 各一条），是配置叠加造成的。精确匹配会覆盖 `sw.js`、manifest 和 `index.html`。

## 4. 第 3 步：生效并自检

```bash
docker exec openresty nginx -t && docker exec openresty nginx -s reload
```

服务器上自检（逐条对比期望值）：

```bash
curl -sI http://127.0.0.1/sw.js | grep -i cache-control
curl -sI http://127.0.0.1/manifest.webmanifest | grep -iE 'content-type|cache-control'
curl -sI http://127.0.0.1/index.html | grep -i cache-control
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/api/health
curl -sI http://127.0.0.1/assets/index-C5u0Ch3a.js | grep -i cache-control
```

| 命令 | 期望 |
| --- | --- |
| `/sw.js` | `Cache-Control: no-cache` |
| `/manifest.webmanifest` | `Content-Type: application/manifest+json` 且 `Cache-Control: no-cache` |
| `/index.html` | `Cache-Control: no-cache` |
| `/api/health` | `404` |
| `/assets/index-C5u0Ch3a.js` | 仍为 `max-age=604800` |

外网复验（回到本机执行）：

期望：失败 0，警告仅剩"HTTP 环境无 Service Worker"和"根路径引用"两条。

## 5. 第 4 步：失败回滚

```bash
cp /opt/1panel/www/conf.d/cet-word-web.conf.bak-<时间戳> /opt/1panel/www/conf.d/cet-word-web.conf
docker exec openresty nginx -t && docker exec openresty nginx -s reload
```

站点整体异常时：旧容器 `cet-word-web` 与旧目录 `/opt/cet-word-web/releases/20260919-0206` 是回退资产，可临时恢复，不要删除。

## 6. 禁止动作

- 不安装或卸载 MySQL / MariaDB / Redis 等任何数据库；不动 1Panel 面板端口与安全入口
- 不修改 MySQL 凭据，不新建数据库用户，不导出任何数据
- 不删除旧容器、旧发布目录（回退资产）
- 不在服务器上放开 3000 / 3306 / 6379 等端口
- 不做域名、DNS、证书相关工作（用户尚未确定域名）
- 不执行 `rm -rf`、不重装 OpenResty、不改 `/opt/1panel` 之外的系统配置
