# 用户流程与数据交互核对（2026-09-22）

## 测试边界

本机没有 MySQL、Docker 或 3306 服务，因此本次使用项目的本地内存测试仓储和 Fastify API 完成流程核对。它验证真实的路由、会话、授权和仓储调用路径，但不等同于真实 MySQL 的 SQL 执行验收。测试服务停止后，所有测试账号和数据都会清空。

## 浏览器流程

1. 管理员登录独立后台。
2. 管理员创建 `journey@example.test` 测试账号。
3. 新账号登录学习前台。
4. 新账号加载 3 个示例词。
5. 新账号开始新学并完成 3 个词。
6. 页面显示“新学任务已完成”，API 日志显示学习提交成功。

浏览器日志中的关键请求均返回成功：管理员登录和权限检查、`POST /api/admin/users`、新用户登录、`POST /api/words/import`、三次 `PUT /api/review/draft`、`POST /api/study/new/complete`，以及随后重新读取词库、事件、设置、到期队列和草稿。

## 仓储快照

同一套 Fastify 路由和内存仓储的逐步快照如下：

| 阶段 | 观察结果 |
| --- | --- |
| 管理员创建 | 创建普通账号；审计记录为 `create_user`，操作者和目标用户 ID 分开记录 |
| 新用户登录 | 返回 200 并签发会话；没有输出会话令牌 |
| 导入词库 | 3 个词条，3 个词条的 `userId` 全部等于新用户 ID |
| 保存设置 | `user_settings.userId` 等于新用户 ID；每日计划写入 3/1/3 |
| 保存草稿 | `review_drafts` 产生 `active` 草稿，`revision=1`，归属新用户 |
| 完成新学 | `completed=3`；3 条进度记录进入已学习状态；3 条 `learning_events(kind=new)` 归属新用户；产生 1 条 `review_submissions(kind=new)` |
| 隔离检查 | 管理员搜索能看到目标账号；普通用户请求管理员列表返回 403；管理员自己的词条数为 0 |

## 结论与下一步

应用层的用户创建、会话、数据写入和 `userId` 隔离路径符合预期，浏览器流程和后台请求日志相互吻合。真实 MySQL 仍需在有数据库的环境运行 `RUN_MYSQL_TESTS=1` 的集成测试，才能补齐 SQL、外键级联、事务和索引层面的证据；本机没有连接生产数据库，也没有改动线上数据。
