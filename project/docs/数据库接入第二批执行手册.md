## 4. API 契约

所有接口身份只能来自 HttpOnly 会话 Cookie；不接受 body/query 中的 userId。错误返回 JSON。

### 设置与统计

- `GET /api/settings`
- `PATCH /api/settings`
- `GET /api/events`：当前用户分页或最近 5000 条，不能读其他用户。

### 学习队列

- `GET /api/review/due`：返回服务端计算后的当前任务，支持有限 `limit`。
- `GET /api/spelling?scope=daily|library&filter=...&limit=...`：只返回当前用户范围内的词。
- `GET /api/review/draft?key=...`
- `PUT /api/review/draft`：按 `draft_key` 保存，限制 payload 大小，支持 revision 冲突返回 409。
- `DELETE /api/review/draft?key=...`

### 完成提交

- `POST /api/study/new/complete`
- `POST /api/review/complete`
- `POST /api/spelling/complete`

每个完成请求必须包含：

- 客户端生成的 `submissionKey`，长度和字符集受限；重复 key 返回第一次结果。
- 词条 ID + 客户端提交时看到的 `updatedAt` / `nextReviewAt` 版本信息。
- 认词与拼写答案只作为输入；服务端读取当前数据库进度并计算结果。

冲突规则：词已删除、斩词、版本/到期时间不一致时，该词不应覆盖新状态；返回明确的冲突/跳过统计。整批写入必须使用事务；中途失败不得留下半批进度、事件或提交记录。

## 5. 规则必须与 localStore 一致

以 `app/src/data/localStore.ts` 为行为基准，不改产品规则：

- review interval：`1 / 2 / 4 / 7 / 15 / 30 / 60` 天。
- stage 范围 0—6；recognition/spelling score 范围 0—5。
- recognition 出错：`again`，stage 减 2，最低 0。
- 认词正确但拼写出错：`hard`，stage 不变。
- stage >= 3 且两项历史分数 >= 3，本轮全对：`easy`，stage 加 2，最高 6。
- 其他全对：`good`，stage 加 1，最高 6。
- 新学完成：不伪造认词/拼写成绩，只设置 firstLearnedAt、lastReviewAt 和明天到期，并写 `learning_events(kind=new)`。
- 独立拼写：只更新 spelling score/result；拼错时下次不晚于明天；不推进 stage，不写 review event。
- 复习完成写 `learning_events(kind=review)`，并更新计数和最近结果。
- 数据库时间统一 UTC；每日计划按用户 timezone 计算，默认 `Asia/Shanghai`。

不要复制出第二套相互矛盾的算法；优先抽取纯函数到 `server/src/learningRules.ts`，由 fake 测试直接覆盖。

无 MySQL 必须通过：

- 设置默认值、边界和用户隔离。
- due 队列顺序：已学到期优先、新词按计划限额。

- 事务失败时 fake 状态不产生半批写入；fake 测试必须明确标注不是 MySQL 集成测试。

有 MySQL 环境时才运行真实 migration/SQL 集成测试；当前没有，不得伪造。

## 7. 安全与停手条件

- payload、submissionKey、词条列表和批量大小必须有上限。
- SQL 全部使用参数化查询；动态排序只能来自白名单。
- 复习接口不能信任客户端传入 stage、score、nextReviewAt、userId。
- 日志不得打印密码、Cookie、token、完整 draft 或备份。
- 未实现可靠事务/幂等/冲突保护时停止，不要宣布完成。
- 依赖安装失败、Node/lockfile 不兼容、发现生产凭据或需要服务器操作时停止。
- 不用明文密码、SHA-256 代替 argon2、客户端最终结果代替服务端计算。
