## 1. 本批完成定义

只有以下全部满足，才报告“第一批完成”：

1. 新增独立 `server/` 后端目录，不把后端代码塞进 `app/`。
2. 新增独立 MySQL migration，使用 InnoDB、utf8mb4、UTC 时间；不引用 Supabase/Auth/RLS/PostgreSQL 语法。
3. 提供健康检查、就绪检查、登录会话和词库基础接口。
4. 所有用户数据从服务端会话得到 `user_id`；请求体和 URL 中的用户 ID 不得决定权限。
5. 词库唯一约束为 `(user_id, normalized_word)`；进度唯一约束为 `(user_id, word_id)`。
6. SQL 全部参数化；密码不明文存储；会话材料不放 localStorage。
7. 关键 API 有自动化测试：未登录、越权、重复导入、重复删除和健康检查至少覆盖。
8. 不改变当前前端 repository、localStore、TSV、复习算法和备份格式；现有测试/构建仍能运行。
9. 提供 `.env.example`、启动说明和 OpenResty 代理说明；不得写入真实密码、Cookie、数据库地址或服务器凭据。
10. 输出结构化报告，列出实际运行过的测试、未运行的 MySQL 集成测试和下一批阻塞项。

## 2. 技术决策（不要自行改路线）

- 后端：Node.js + TypeScript + Fastify。
- 数据库：MySQL 8.x，驱动 `mysql2`。
- 输入校验：`zod` 或同等明确 schema 校验库；不要只靠 TypeScript 类型。
- 密码哈希：优先 `argon2`；若当前 Node/平台无法安装原生依赖，停手报告，不得降级为明文、SHA-256 或自制哈希。
- 会话：随机不可预测 token 的哈希存 `auth_sessions`，原 token 只通过同源 HttpOnly Cookie 发给浏览器；开发环境可不启 Secure，生产必须 Secure。
- API 路径：同源 `/api`；第一批本地测试可以直接调用 Fastify app，不要求前端立即切换异步 repository。
- 数据库时间：UTC；用户设置默认 `Asia/Shanghai`。
- 查询：使用参数化 SQL；不能拼接用户输入到 SQL、表名或排序片段。
- 事务：导入批次使用事务；复习提交接口本批可以先留接口边界，但不得伪造“已实现”。

## 5. MySQL migration 必须包含的表

第一批至少创建以下表；字段名可采用 snake_case，但要与现有 `app/src/types.ts` 对得上：

### users

- `id`：服务端生成的稳定 ID
- `email`：规范化后唯一
- `password_hash`
- `username`、`avatar`
- `timezone`，默认 `Asia/Shanghai`
- `created_at`、`updated_at`

### auth_sessions

- `id`
- `user_id` 外键
- `token_hash` 唯一
- `expires_at`、`revoked_at`、`created_at`
- 适合按 `user_id`、`expires_at` 建索引

### words

- `id`、`user_id` 外键
- `normalized_word`、`word`
- `phonetic`、`meaning`、`phrase`、`sentence`、`sentence_cn`、`source`、`type`
- `created_at`、`updated_at`
- `UNIQUE(user_id, normalized_word)`

### word_progress

- `id`、`user_id`、`word_id`
- `review_stage` 0—6
- `recognition_score`、`spelling_score` 0—5
- `first_learned_at`、`next_review_at`、`last_review_at`
- 最近认词/拼写结果、`last_grade`
- `killed_at`、`last_restored_at`
- `review_count`、`correct_count`、`wrong_count`
- `version` 用于后续乐观锁
- `UNIQUE(user_id, word_id)`，并用复合外键保证词条归属一致

### learning_events

- `id`、`user_id`、`word_id`
- `occurred_at`、`kind`、`review_stage`
- 用于迁移当前 `learningEvents` 和统计趋势

### user_settings

- `user_id` 主键/外键
- `daily_target`、`daily_groups`、`daily_group_words`
- `timezone`、`countdown_label`、`countdown_target_date`
- `updated_at`

本批可以先不实现 `review_sessions`、`review_drafts`、`review_logs`、`import_batches` 的完整业务，但应在 `database/README.md` 说明它们属于下一批，不能声称复习云端同步已经完成。

## 6. 第一批 API 契约

### 健康

- `GET /api/health`：进程存活，返回 `{ "ok": true }`，不连接数据库也可返回。
- `GET /api/ready`：检查配置和数据库连接；数据库不可用必须返回非 2xx，不得返回首页 HTML 或伪造成功。

### 认证

- `POST /api/auth/login`：邮箱 + 密码；成功设置 HttpOnly 会话 Cookie，返回不含密码的用户资料。
- `POST /api/auth/logout`：撤销当前会话并清 Cookie。
- `GET /api/auth/me`：返回当前用户或 401。

首个账号创建必须使用一次性初始化命令或受保护的 seed 流程，不开放公开注册；没有明确实现前，不要新增 `POST /register`。

### 词库

- `GET /api/words`：只返回当前会话用户的词条和进度；支持有限分页，不接受 `userId` 作为权限依据。
- `POST /api/words/import`：接收现有 `WordInput[]`，服务端重新规范化、校验、按用户合并；重复导入不重复建词，不重置已有进度。
- `PATCH /api/words/:id`：只允许更新音标和释义等明确字段，检查词条归属。
- `DELETE /api/words/:id`：只删除当前用户的词条及关联进度；不存在或他人 ID 不泄露信息。
- `POST /api/words/:id/kill`、`restore`、`undo-kill`：保持现有语义，均检查归属。

本批不把前端改成远程 API；API 通过测试证明可用后，下一批才改异步 repository 和页面 loading/error/retry。

## 7. 测试要求

### 无 MySQL 时必须可运行

- 健康路由测试。
- 配置校验测试：缺少秘密、非法端口、非法 cookie 配置应失败。
- schema/规范化测试：邮箱、单词、type、分数边界。
- 认证测试：错误密码 401、会话 Cookie 属性、logout 撤销。
- 路由权限测试：没有 userId 参数也能识别当前用户；不同用户不能读写彼此词条。

可以使用注入的 fake repository 或测试 double，但不能把 fake 结果写成 MySQL 集成测试。

### 有 MySQL 时才运行

若环境提供明确的测试 MySQL 连接，才运行 migration 和集成测试；使用独立测试库与测试账号。报告中必须写明 `MYSQL_TEST_*` 是否存在。禁止连接线上生产库。

## 8. 环境变量与安全边界

新增 `.env.example` 只放占位符：

```text
NODE_ENV=development
API_PORT=3000
APP_ORIGIN=http://localhost:4173
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=cet_words
MYSQL_USER=cet_words_app
MYSQL_PASSWORD=
SESSION_SECRET=
COOKIE_SECURE=false
```

要求：

- `MYSQL_PASSWORD`、`SESSION_SECRET` 只能在后端运行环境；不得以 `VITE_*` 前缀出现。
- `.env`、`.env.*`（保留 `.env.example`）必须被 Git 忽略。
- 日志不得打印密码、Cookie、token 原文或完整备份内容。
- 生产数据库用户不应拥有建库/删库权限；migration 使用单独账号。

## 9. 停手条件与禁止动作

遇到以下任一情况，立即停止并报告，不要自行换方案：

- 依赖安装需要访问不明外部源、真实凭据或付费服务。
- 发现 Node/TypeScript 版本与项目锁定环境不兼容。
- 无法使用参数化查询或无法隔离用户数据。
- `argon2` 无法安装且没有经审查的安全替代。
- migration 需要修改/删除现有线上数据。
- 发现 3306 对公网监听、生产数据库连接信息或真实备份。
- 前端原有测试/构建失败且原因不属于本批新增代码。
- 需要重写 `App.tsx`、删除 localStore 或改变 TSV/备份格式。

禁止：

- `git reset --hard`、`git clean -fd`、`git checkout --`。
- 执行 `project/archive/supabase/` SQL。
- 安装或启动生产 MySQL；不 SSH、不碰 1Panel。
- 发送、提交或打印任何秘密。
- 把数据库错误吞掉后返回 200，或让 `/api/*` 回退到 `index.html`。
