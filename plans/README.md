# CET46 可维护性改进执行看板

日期：2026-09-20。状态：本地首轮实现与回归完成，线上未变更；真实 MySQL、HTTPS、迁移和备份恢复尚未放行。

## 已确认的产品决策

- 维护目标是通过 1Panel 操作，不要求移除面板底层 Docker。
- 管理员仅本人；第一版创建账号、启停账号、重置密码，不读取朋友学习内容。
- 保留 Fastify、MySQL、邮箱密码与 Session。参考开源项目的组织和交互设计，不替换整个技术栈。
- 实现代理使用 gpt-5.6-luna；主代理复核接口、权限、迁移与验收结果。实际费用依账户计费，未承诺精确价格。

### T1 目录与维护

1. 前端源码按 `app/src/components`、`pages`、`features`、`data`、`styles` 分类；新增模块按类放置，不一次搬走整个App。
2. 保留 `app/public` 给原样发布资源；manifest与sw.js留在网站根保证作用域/引用，图标若移动必须同步HTML/manifest/SW所有引用。
3. 构建产物始终整包发布。JS/CSS的hash命名合理，禁止在服务器手工改名；如需要assets/js、assets/css，应修改构建规则并验证全部引用后统一生效。
4. 后端源码、迁移、运行秘密、备份分别管理；MySQL已有数据目录保留面板默认位置，不能为“整齐”随意移动。
5. 比对现有两套deploy文档，建立唯一当前入口；旧方案标历史/备用，确认引用后才迁移文件。
6. 维护指南必须逐项给出“看日志、重启API、备份、更新、回滚、创建账号”的面板点击路径。
7. 验收：新人按指南能找到真实资源；当前文档不再指向不适用的网络模型；旧资产有明确回退用途。

### T2 交互与适配

1. 为已观察到的320窄屏标题拥挤、模态遮挡写最小修复计划。
2. 模态框挂载到document.body或等价独立顶层，统一视口高度、内部滚动、安全区、焦点管理；保持原保存语义。
3. 小屏标题/工具栏允许分行布局，减少装饰占用；桌面保持合理内容最大宽度。
4. 高频答题/输入以即时响应为先；偶发弹窗使用既有ease token和transform/opacity，移除会触发布局的动画。
5. 在320/390/768/1440宽度检查首页、导入、词库、学习、统计、设置；验证长词、长用户名、100/200%缩放、软键盘和减少动态效果。
6. 自动检查通过后用浏览器交互复核；Safari与真机测试未做时明确标待验收。

### T3/T4 最小管理员

1. 设计管理员身份的服务端唯一来源，默认无管理员；初次将既有本人账号纳入管理权限，不能公开自助提权。
2. 增量迁移添加禁用状态和必要审计记录；保留用户与词库数据，禁用不删除用户。
3. 新增受控账号列表/创建/状态变更/重置密码API；Session鉴权、管理员校验、同源检查、参数白名单必须同时存在。
4. 禁用或重置密码时撤销目标账号旧Session；不能禁用自己导致管理入口锁死；普通资料接口不得写管理员/禁用字段。
5. 密码沿用Argon2id，不回传摘要、不写日志；后台不提供词库/学习内容浏览API。
6. 图形界面仅管理员可见，表单含校验、保存中/失败/重试，敏感输入提交后清空，列表不显示密码。
7. 测试游客401、普通用户403、管理员成功、重复邮箱409、禁用账号拒绝新登录和旧会话、重置后旧密码失效及旧Session撤销、朋友学习数据保持不变。
8. 本地测试通过后才进入线上迁移；HTTP阶段不作为正式账号管理验收，先完成HTTPS。

### T5 数据与备份

1. 校验session来源身份、SQL user_id条件、复合外键/索引、事务、submissionKey、draft revision。
2. 检查加载全量事件与词库的成本、重复hydrate/竞争，不因微小设置变更重新拉取全部历史；根据证据实施最小修复。
3. 在隔离测试数据库用Alice/Bob分别创建同名单词、相同draft/submission key，验证读写/学习隔离与跨设备冲突。
4. 为运行账号限制为实际必需DML，迁移账号才拥有DDL；先在测试验证迁移/创建用户所需权限，维护脚本不得依赖运行账号建表。
5. 1Panel数据库备份采用日7/周4策略；备份放网站根之外，配置独立存储目标与访问权限。
6. 将备份恢复到独立临时数据库，核对行数、约束及抽样进度，保留可追踪结果；未经确认不删除现有库或备份。

### T6/T7 上线与验收

1. 保留旧静态发布目录与旧API服务；先准备Node24面板运行环境，在备用回环端口验证argon2、环境读取和DB连接。
2. 运行前端/后端测试、类型检查、构建；真实MySQL集成测试需独立库且不可skip冒充通过。
3. 备份数据库后增量迁移两次验证幂等；记录结构版本。
4. API ready通过后切同源/api上游，再切完整前端产物；API错误保持JSON和原状态码。
5. 域名/DNS/HTTPS确定后启用生产配置和Secure Cookie；轮换测试阶段出现过明文显示风险的DB/Session秘密，操作值不进入聊天。
6. 对两个普通账号和管理员账号验收登录、导入、学习、设置、草稿、断网、重复提交、会话失效；真实设备同步完成后签收。
7. 发布记录写明源码版本、构建指纹、迁移版本、备份位置、回滚步骤和未测项。

所有状态以实测证据为准。管理员实现、安全配置和数据恢复未完成前，不把“页面能打开”标记为本轮全部完成。

- 管理员API、增量003迁移、受控提升管理员CLI已添加，未在生产执行。默认仍为普通账号；不提供公开注册和角色修改界面。
